# AI Agent Coordination

Use `AGENTS.md` as the only repository routing and architecture source of
truth. Use `docs/specs/README.md` as the SDD policy and document-role source of
truth.

## Entrypoints

- Copilot CLI: `.github/copilot-instructions.md`
- Codex custom-agent definitions: `.codex/agents/*.toml`
- Role-owned reusable procedures: `.agents/skills/*/SKILL.md`
- Skill invocation adapters: `.agents/skills/*/agents/openai.yaml`

## Routing

Main is the default chat entrypoint and repository orchestrator. Main handles
ad-hoc discussion, investigation, analysis, troubleshooting, scope
clarification, informal feedback, routing classification, and SDD discussion
directly; SDD subject matter alone does not activate a role. Formal
role-owned operations are delegated one at a time as `Main -> Child -> Main`.
Each child returns its result, evidence, and recommended route; Main decides
whether a later role is needed and preserves all safety and approval gates.

Follow the deterministic SDD routing in `AGENTS.md` for formal operations:

`Main → feature-author → Main → plan-author → Main → plan-reviewer → Main` →
Human Approval → `Main → approval-committer → Main` →
`Main → implementer → Main → implementation-reviewer → Main` → Completion
Approval → `Main → approval-committer → Main` →
`Main → feature-closer → Main` → Closure Approval →
`Main → approval-committer → Main`.

Findings and scope, design, impact, or approval-boundary blockers return to
Main for routing. The catalog is seven SDD lifecycle roles plus the
`approval-committer` gate role; `$release-extension` uses its canonical release
procedure and remains outside the SDD lifecycle.

This file is an index only. Do not duplicate SDD policy, role authority,
model assignments, or procedure checklists here.
