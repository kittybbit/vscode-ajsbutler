## Planning Evidence

- Selected feature and branch are unambiguous; this branch owns only
  `docs/specs/features/semantic-diff-comparison-workflow/` over roadmap commit
  `97d5ccfd`. Main's roadmap dependency correction is a parent-branch change,
  not part of this feature folder.
- Current code was inspected in `semanticDiffCommand.ts`,
  `semanticDiffWiring.ts`, `extensionDependencies.ts`,
  `buildSemanticDiffReportData.ts`, `compareSemanticDiff.ts`, `package.json`,
  and the focused tests. The current source-text input has only
  `beforeContent`/`afterContent`; it has no period field.
- The future calendar adapter contract and Explorer same-pass source-capture
  contract are consumed only after their completion commits. The workflow
  implementation gate verifies exact `options.scheduleComparisonPeriod`, the
  workflow-owned injected capture/parser callback (with Explorer's
  current-file builder independent and any future calendar callback optional),
  closed `bind(context)` result, the
  `collecting` → `bound` → `registered` → `released` lifecycle,
  `unregister(context, scope)` before one `scope.release()`, the one-argument
  `OpenSemanticDiffExplorer(context)`, opaque source handles, and the concrete
  session/disposal API; any mismatch routes Replanning to the owning feature
  instead of adding a shim.
- VS Code 1.75 Git API v1 evidence covers `getAPI(1)`, `getRepository`,
  `getObjectDetails(treeish, path)`, `detectObjectType(object)`, and
  `show(ref, path)`. Its `RepositoryState` exposes `indexChanges` and
  `workingTreeChanges` but no separate untracked array; configured hidden or
  separate untracked presentation therefore cannot be used to assert status.
  The adapter captures `state.HEAD.commit` once, passes that immutable hash to
  object inspection and `show`, and returns the stable `HEAD` label. The
  1.75 status model uses `INDEX_RENAMED`/`INDEX_COPIED` and working
  `MODIFIED`/`DELETED` with optional `renameUri`; no invented generic rename
  or copy enum is used. The 1.75 implementation raises
  `GitErrorCodes.UnknownPath` for an absent `ls-tree` path; only that code
  permits the current-path rename fallback, while candidate `UnknownPath`
  maps to `head-source-missing` without retry and other errors remain stable
  provider/API/read failures. Its `Encoding` enum returns `utf8`, `utf16be`,
  or `utf16le` from `detectObjectType`; unknown advertised values are
  rejected, while `show` remains the decoded/textconv source. Raw blob bytes
  are not a workflow input.
- Git-before navigation also requires a browser-safe
  `ajsbutler-git-head:` content provider with a collision-free opaque key per
  command-scoped snapshot reservation before context creation, association to
  the exact context only after successful binding, no repository path in the
  URI, a fixed eight-active-entry cap with typed `capacity-exceeded`
  rejection, released-entry eviction, and fail-closed stale reveals. This map
  is owned by the workflow's
  infrastructure/bootstrap composition and is covered by source lifecycle
  tests rather than by Explorer wire data.
- Approval state and scope are recorded in `TASKS.md`; runtime implementation
  remains deferred to its separate slice gates.
